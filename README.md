# Yandex 360 — массовое изменение default_email

CLI на Python для назначения сотрудникам адреса отправителя по умолчанию: выгрузка → редактирование CSV → проверка → подтверждение → PATCH → отчёт. Только стандартная библиотека, установка пакетов не нужна.

## Требования

- Python 3.9 или новее.
- ID организации и OAuth-токен с доступом к организации и разрешением `directory:write_users`.
- Сетевой доступ к `cloud-api.yandex.net`.

Токен вводится скрыто при запуске. Также поддерживается переменная окружения `Y360_TOKEN`. Не записывайте токен в код, CSV или Git.

## Быстрый старт

Откройте терминал в папке проекта и выполните:

```bash
python3 default_email.py --org-id 123456
```

1. Скрипт получает всех сотрудников с пагинацией и сохраняет CSV и снимок исходных значений рядом со скриптом.
2. Откройте созданный `users_*.csv`. Заполните **четвёртую** колонку `default_email` только для нужных сотрудников.
3. Сохраните файл в UTF-8 с разделителем `;`, закройте редактор и введите `READY` в CLI.
4. Скрипт проверит весь CSV, повторно прочитает данные организации и покажет список изменений.
5. Введите показанную фразу, например `APPLY 123456 2`. Затем начнутся последовательные PATCH.
6. Результаты появятся в терминале и в `users_*.results_*.jsonl`.

Все файлы создаются в папке скрипта независимо от текущей папки терминала. Существующие выгрузки не перезаписываются.

## CSV

```csv
email;id;name;default_email
ivan@example.org;1130000000000001;Иванов Иван;ivan@example.com
anna@example.org;1130000000000002;Петрова Анна;
```

| Колонка | Назначение |
| --- | --- |
| `email` | Исходный основной email из GET. Не изменять. |
| `id` | UID сотрудника из GET. Не изменять. |
| `name` | Фамилия, имя, отчество из объекта `name`. Не изменять. |
| `default_email` | Новый адрес отправителя. Пусто — пропустить сотрудника. |

При импорте в Excel задайте колонкам тип **Текст**: UID нельзя округлять или преобразовывать в экспоненциальную запись. Надёжнее редактировать CSV текстовым редактором. Разделитель и заголовки должны сохраниться. Значения, похожие на формулы, в служебных колонках получают защитный апостроф — не удаляйте его.

Можно удалить строки ненужных сотрудников; добавлять неизвестные UID нельзя. Не изменяйте файл `.snapshot.json`: он связывает выгрузку с организацией и хранит исходные значения для проверки конфликтов. Это локальная проверка согласованности, не криптографическая защита от изменения файлов.

## Другие режимы

Только выгрузить:

```bash
python3 default_email.py --org-id 123456 --export-only
```

Проверить ранее сохранённый файл без изменений в организации:

```bash
python3 default_email.py --org-id 123456 --apply users_20260927T180000Z_ab12cd34.csv --dry-run
```

Продолжить после закрытия терминала или ошибки:

```bash
python3 default_email.py --org-id 123456 --apply users_20260927T180000Z_ab12cd34.csv
```

CSV и одноимённый `.snapshot.json` должны находиться в папке проекта. `--apply` снова выполняет GET и пропускает уже установленные адреса. Если адрес после выгрузки изменился на другое значение, нужна новая выгрузка.

## Результаты и ошибки

Журнал JSONL содержит UTC-время, UID, целевой адрес, статус и краткую причину ошибки. Он сохраняется после каждой записи:

- `started` — запрос сейчас отправляется; если итоговой записи нет, результат неизвестен.
- `success` — ответ PATCH подтвердил UID и новый адрес.
- `failed` — API вернул ошибку.
- `unknown` — таймаут, серверная ошибка либо ответ не подтвердил изменение. Запись могла измениться на сервере.
- `skipped_empty` / `skipped_equal` — пустая ячейка / адрес уже установлен.

При 401, 403, 429 или неизвестном результате пакет останавливается. Остальные ошибки отдельных сотрудников фиксируются, обработка продолжается. Строки после остановки не отправлялись. GET повторяется до трёх попыток при сетевых ошибках, 429 и 5xx; PATCH автоматически не повторяется. После исправления причины запустите `--apply`: свежий GET поможет избежать повторения выполненных изменений.

Коды завершения: `0` — успешно, проверка без изменений или отмена подтверждения; `1` — ошибка / частичное выполнение; `2` — ошибка аргументов; `130` — Ctrl+C или закрытие ввода. Автоматического отката нет. Между проверкой и PATCH возможны параллельные изменения другим администратором — согласуйте окно работ.

Адрес проверяется локально только на базовый формат; возможность его назначения определяет API. Скрипт не создаёт алиасы и не подключает домены. Выгружаются все сотрудники, включая записи заблокированных и уволенных: изменение выполняется только при заполненной ячейке.

## Проверка разработки

```bash
python3 -B -m unittest -v
```

Тесты используют искусственные данные и подменённый HTTP-клиент, не обращаются к организации. Реальную интеграцию следует проверить на одном сотруднике с вашим токеном.

CSV, снимки, журналы и локальные секреты исключены через `.gitignore`. Они содержат данные сотрудников, поэтому не добавляйте их в публичный репозиторий.
